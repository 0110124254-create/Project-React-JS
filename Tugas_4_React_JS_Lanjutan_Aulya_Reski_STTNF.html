1. Deskripsi & Tujuan Pembelajaran

Tugas ini bertujuan menambahkan pengaturan routing dan service otorisasi pada proyek Ruang Baca berbasis React JS untuk membatasi hak akses antara pengguna biasa (user) dan administrator (admin) melalui penerapan prinsip Protected Route dan Role-Based Access Control (RBAC).

  • Memahami konsep Protected Route: Melindungi halaman privat dari akses tanpa autentikasi dan otorisasi.
  • Navigasi Berdasarkan Peran (Role-Based Access): Membedakan rute yang boleh dibuka oleh Admin, User, dan Pengunjung Publik (Guest).
  • Meningkatkan Keamanan & Struktur Frontend: Menggunakan Context API terpusat (AuthContext) dan sinkronisasi localStorage untuk persistensi sesi yang andal.

2. Matriks Hak Akses Pengguna (Access Control Matrix)

Rute / Halaman Pengunjung (Guest) Pengguna Biasa (User) Administrator (Admin)
Beranda (/) & Katalog (/books) ✔ Buka Bebas ✔ Buka Bebas ✔ Buka Bebas
Masuk (/login) & Daftar (/register) ✔ Buka Form ↳ Auto Redirect ke Profil ↳ Auto Redirect ke /admin
Profil Pengguna (/user/profile) ⛔ Redirect ke /login ✔ Diizinkan ✔ Diizinkan
Admin Dashboard (/admin) ⛔ Redirect ke /login ⛔ Ditolak (403 Unauthorized) ✔ Hak Akses Penuh
CRUD Genre & Penulis (/admin/*) ⛔ Redirect ke /login ⛔ Ditolak (403 Unauthorized) ✔ Hak Akses Penuh

3. Rincian Arsitektur Teknis yang Diimplementasikan

A. Service Otorisasi Terpusat (src/context/AuthContext.jsx)

Menggunakan React Context API dan custom hook useAuth() untuk menyediakan status autentikasi reaktif ke seluruh aplikasi:

  • user & token: Disinkronkan otomatis dari/ke localStorage saat reload.
  • isAuthenticated: Memastikan pengguna memiliki token aktif dan data pengguna yang valid.
  • isAdmin: Logika evaluasi peran (role === 'admin' || is_admin === true).
  • login(credentials), logout(), dan switchDemoRole(targetRole).

B. Guard Terproteksi Berbasis Peran (src/components/ProtectedRoute.jsx)

Komponen pencegat rute cerdas yang memeriksa parameter allowedRoles:

  • Jika pengunjung belum login: Otomatis dialihkan ke /login dengan parameter lokasi asal (state.from).
  • Jika pengguna telah login tetapi perannya tidak terdaftar di allowedRoles (misal: user biasa mencoba membuka rute admin): Langsung dialihkan ke halaman khusus /unauthorized (403 Forbidden).

C. Halaman 403 Akses Ditolak (src/pages/auth/unauthorized.jsx)

Halaman 403 modern dan ramah pengguna yang menampilkan nama pengguna aktif, label peran saat ini, URL administratif yang dicegat, serta tombol aksi cepat untuk beralih ke profil pengguna atau mengganti akun ke administrator.

D. Dashboard Pengguna Biasa (src/pages/user/profile.jsx)

Menyediakan ruang personal bagi pengguna biasa (role: user), memuat kartu profil, metrik bacaan, dan fitur interaktif "Uji Penolakan Akses /admin" yang memungkinkan penguji melihat secara langsung sistem pencegatan rute bekerja.

E. Fitur 1-Klik Login Demo untuk Penguji (src/pages/auth/login.jsx)

Disediakan tombol preset instan pada form masuk untuk mempermudah evaluasi tugas tanpa perlu mengetik manual:
• 👑 Masuk Admin: admin@ruangbaca.com / password123 (Akses Penuh ke /admin).
• 👤 Masuk User: user@ruangbaca.com / password123 (Akses Terbatas ke /user/profile).

4. Cuplikan Kode Program Utama

A. Implementasi Guard Rute (src/components/ProtectedRoute.jsx)

export default function ProtectedRoute({ allowedRoles = [] }) { const { user, isAuthenticated, role, loading } = useAuth(); const location = useLocation(); if (loading) return <LoadingSpinner />; // 1. Belum login sama sekali -> Arahkan ke /login if (!isAuthenticated) { return <Navigate to="/login" state={{ from: location.pathname }} replace />; } // 2. Login, tapi peran tidak memenuhi syarat -> Arahkan ke 403 Unauthorized if (allowedRoles.length > 0 && !allowedRoles.includes(role)) { return ( <Navigate to="/unauthorized" state={{ attemptedPath: location.pathname, userRole: role, requiredRoles: allowedRoles }} replace /> ); } return <Outlet />; }

B. Konfigurasi Routing Berjenjang (src/App.jsx)

<AuthProvider> <Routes> {/* Rute Publik */} <Route element={<PublicLayout />}> <Route path="/" element={<Home />} /> <Route path="/books" element={<Books />} /> </Route> {/* Rute Terproteksi Khusus Pengguna & Admin */} <Route element={<ProtectedRoute allowedRoles={["user", "admin"]} />}> <Route path="/user/profile" element={<UserProfile />} /> </Route> {/* Rute Terproteksi Khusus Administrator */} <Route element={<ProtectedRoute allowedRoles={["admin"]} />}> <Route path="/admin" element={<AdminLayout />}> <Route index element={<Dashboard />} /> <Route path="genres" element={<AdminGenres />} /> <Route path="authors" element={<AdminAuthors />} /> </Route> </Route> <Route path="/unauthorized" element={<Unauthorized />} /> </Routes> </AuthProvider>

5. Petunjuk Pengujian Hak Akses

  1. Buka aplikasi di http://localhost:5173/login.
  2. Klik tombol "👤 Masuk User". Anda akan diarahkan ke /user/profile.
  3. Coba ketikkan URL /admin di browser atau klik tombol "Coba Akses /admin" pada profil. Amati bahwa sistem langsung menolak dan mengarahkan Anda ke 403 Akses Ditolak.
  4. Klik tombol "Ganti Akun ke Administrator". Sistem akan mengautentikasi ulang sebagai Admin dan mengizinkan Anda masuk ke /admin secara penuh.
